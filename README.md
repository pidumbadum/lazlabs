# Lazlabs School Management System

Веб-система управления образовательным центром для автоматизации расписания, домашних заданий, бухгалтерии и ролевого доступа пользователей.

## О проекте

Lazlabs — это веб-приложение на базе Flask для управления учебным процессом. Система поддерживает три роли пользователей: директор, учитель и ученик.

Основные возможности:
- Управление пользователями и учебными группами.
- Составление расписания с автоматической проверкой временных конфликтов.
- Назначение, сдача и проверка домашних заданий.
- Финансовый учёт (оплаты учеников, расчёт выплат учителям, прибыль).
- Система уведомлений для преподавателей.

## Быстрый старт

### Запуск через Docker (рекомендуется)

    git clone https://github.com/yourusername/lazlabs-school.git
    cd lazlabs-school
    make docker-up

После запуска откройте в браузере адрес http://localhost:5000.

Создание тестового директора через Docker:

    docker exec -it lazlabs-school-app python -c "
    from core import get_db
    from werkzeug.security import generate_password_hash
    db = get_db()
    db.execute('INSERT OR IGNORE INTO users (login, password_hash, role) VALUES (?, ?, ?)',
               ('director', generate_password_hash('admin123'), 'director'))
    db.commit()
    "

Управление контейнерами:

    make docker-logs      # Просмотр логов
    make docker-down      # Остановка контейнеров

### Локальный запуск (для разработки)

    make setup
    make run

После запуска откройте в браузере адрес http://localhost:5000.

## Тестирование

Проект покрыт интеграционными тестами, написанными с использованием pytest. Тесты используют временные файлы SQLite и изолированы от production-данных.

    make test           # Запуск тестов
    make coverage       # Генерация отчёта о покрытии кода (coverage)

Что проверяют тесты:
- Инициализация схемы базы данных.
- Аутентификация, авторизация и разграничение ролей.
- Корректность работы API расписания и заданий.
- CRUD-операции директора (пользователи, группы, предметы).
- Валидация времени и проверка конфликтов в расписании.
- Логика бухгалтерского учёта и система уведомлений.

## API Endpoints

### Аутентификация
- POST /login — вход в систему.
- GET /logout — выход из системы.

### Расписание
- GET /api/schedule — получение расписания на текущую неделю (фильтрация зависит от роли).
- POST /api/schedule/<id>/complete — отметка учителя о проведении занятия.

### Задания
- GET /api/tasks — список заданий.
- POST /api/submit/<task_id> — сдача задания учеником.
- POST /api/grade/<task_id>/<sub_id> — выставление оценки учителем.
- GET /api/submissions/<task_id> — список ответов на задание.

### Управление (только директор)
- POST /api/director/users — создание пользователя.
- GET /api/director/users — список пользователей.
- DELETE /api/director/users/<id> — удаление пользователя.
- GET/POST /api/director/groups — управление учебными группами.
- GET/POST/DELETE /api/director/lessons — управление предметами.
- POST /api/director/schedule — добавление занятия в расписание.

### Функционал учителя
- GET/POST /api/teacher/tasks — создание и просмотр заданий.
- GET /api/notifications — получение уведомлений о пропущенных занятиях и новых ответах.

### Бухгалтерия (только директор)
- GET /api/accounting — финансовая статистика (оплаты, выплаты, прибыль).
- POST /api/accounting — внесение оплаты от ученика.

## Роли и права доступа

**Директор:**
- Создание и удаление пользователей (учителей, учеников).
- Управление учебными группами и предметами.
- Назначение занятий в расписание.
- Просмотр бухгалтерии и внесение оплат.

**Учитель:**
- Просмотр личного расписания.
- Создание заданий для своих групп.
- Проверка работ учеников и выставление оценок.
- Отметка о проведении занятий.
- Получение уведомлений.

**Ученик:**
- Просмотр расписания своей группы.
- Сдача заданий (текст, файл, ссылка).
- Просмотр полученных оценок.
