Архитектура системы
===================

Компоненты
----------

Core Package (``packages/core``)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**Назначение:** Переиспользуемый компонент, содержащий бизнес-логику, не зависящую от интерфейса.

**Содержимое:**

- ``database.py`` — функции работы с БД (``get_db()``, ``init_db()``)
- ``schema.sql`` — SQL-схема базы данных
- ``__init__.py`` — экспорт публичного API

**Особенности:**

- Может быть установлен как отдельный пакет: ``pip install -e packages/core``
- Не зависит от Flask или других веб-фреймворков
- Может использоваться в CLI-утилитах, Telegram-ботах, мобильных приложениях

**Пример использования:**

.. code-block:: python

   from core import get_db, init_db

   # Инициализация БД
   init_db("school.db")

   # Получение соединения
   db = get_db("school.db")
   users = db.execute("SELECT * FROM users").fetchall()

Web Application (``app``)
~~~~~~~~~~~~~~~~~~~~~~~~~

**Назначение:** Веб-интерфейс для взаимодействия с пользователями.

**Содержимое:**

- ``app/main.py`` — Flask-приложение, все HTTP-маршруты
- ``app/templates/`` — HTML-шаблоны (Jinja2)
- ``app/static/`` — CSS, JavaScript, изображения

**Зависимости:**

- Импортирует ``packages/core`` для работы с БД
- Использует Flask для обработки HTTP-запросов
- Использует Jinja2 для рендеринга шаблонов

**Архитектура маршрутов:**

.. code-block:: text

   ├── Аутентификация
   │   ├── POST /login
   │   └── GET /logout
   ├── Дашборд
   │   └── GET /dashboard
   ├── API: Расписание
   │   ├── GET /api/schedule
   │   └── POST /api/schedule/<id>/complete
   ├── API: Задания
   │   ├── GET /api/tasks
   │   ├── POST /api/submit/<task_id>
   │   ├── POST /api/grade/<task_id>/<sub_id>
   │   └── GET /api/submissions/<task_id>
   ├── API: Директор
   │   ├── POST /api/director/users
   │   ├── GET /api/director/users
   │   ├── DELETE /api/director/users/<id>
   │   ├── GET/POST /api/director/groups
   │   ├── GET /api/director/refs
   │   ├── GET/POST/DELETE /api/director/lessons
   │   └── POST /api/director/schedule
   ├── API: Учитель
   │   └── GET/POST /api/teacher/tasks
   ├── API: Бухгалтерия
   │   ├── GET /api/accounting
   │   └── POST /api/accounting
   └── API: Уведомления
       └── GET /api/notifications

Scripts (``scripts``)
~~~~~~~~~~~~~~~~~~~~~

**Назначение:** CLI-утилиты для администрирования и начального заполнения БД.

**Содержимое:**

- ``add_director.py`` — создание учётной записи директора
- ``add_teacher.py`` — создание учётной записи учителя
- ``add_student.py`` — создание учётной записи ученика

**Особенности:**

- Используют ``packages/core`` для работы с БД
- Могут запускаться независимо от веб-приложения

Технологии
----------

Backend
~~~~~~~

- **Python 3.11+** — язык программирования
- **Flask 3.0+** — веб-фреймворк
- **SQLite** — встраиваемая база данных
- **Werkzeug** — хеширование паролей, работа с HTTP

Frontend
~~~~~~~~

- **HTML5** — шаблоны
- **CSS3** — стилизация
- **JavaScript (Vanilla)** — клиентская логика, fetch API

Инфраструктура
~~~~~~~~~~~~~~

- **Docker** — контейнеризация
- **Docker Compose** — оркестрация
- **pytest** — тестирование
- **Make** — автоматизация команд

Принципы проектирования
-----------------------

Разделение ответственности
~~~~~~~~~~~~~~~~~~~~~~~~~~

- Core не знает о Flask
- App не содержит бизнес-логики (только маршруты)
- Tests изолированы от production-данных

Переиспользуемость
~~~~~~~~~~~~~~~~~~

- Core может быть использован в других проектах
- CLI-утилиты используют тот же Core, что и веб-приложение

Воспроизводимость
~~~~~~~~~~~~~~~~~

- Docker гарантирует одинаковое окружение
- ``requirements.txt`` фиксирует версии зависимостей
- ``schema.sql`` воспроизводит структуру БД

Тестируемость
~~~~~~~~~~~~~

- Все API endpoints покрыты тестами
- Тесты используют временную БД
- Нет зависимости от внешних сервисов

Масштабируемость
----------------

Текущие ограничения
~~~~~~~~~~~~~~~~~~~

- SQLite не подходит для высоконагруженных приложений (>1000 одновременных пользователей)
- Файлы хранятся локально (не используется S3 или аналог)
- Нет кеширования (Redis, Memcached)

Пути масштабирования
~~~~~~~~~~~~~~~~~~~~

- Замена SQLite на PostgreSQL/MySQL
- Вынос статических файлов в CDN
- Добавление кеширования
- Горизонтальное масштабирование через load balancer
